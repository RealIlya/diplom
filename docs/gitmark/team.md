# Совместная работа

## Авторы и ответственность

Планируются три самостоятельные ВКР на общей исследовательской платформе.
Инициатор координирует репозиторий. **По его сообщению 11.10.2026 команда
согласовала направления:** маршрутизация, отбор контекста и адаптация модели;
последнее принадлежит инициатору. Канонические вопросы и собственные результаты
записаны в [постановке исследования](research.md#согласованные-направления-трёх-исследований).
Имена двух остальных участников, их руководители и точные названия ВКР
пока не зафиксированы. Согласование направлений командой не является
академическим утверждением тем.

У каждой задачи один ответственный. Общие данные, код измерений и базовый агент
могут использоваться всеми, но у каждой ВКР должны быть собственные задачи,
исследовательский результат и описание личного вклада.
Распределение «один пишет код, второй запускает тесты, третий пишет текст»
не заменяет разделение самостоятельных исследований.

## Git и задачи

1. Перед работой проверить изменения и согласовать границы задачи с другими авторами.
   Задачи сейчас ведутся в [wiki](README.md#ближайшие-задачи).
2. После начального коммита использовать небольшие тематические ветки.
   Для агентских веток — `codex/<topic>`; для человеческих — `research/<topic>`,
   `docs/<topic>` или другое понятное команде имя.
3. Один коммит должен представлять понятное законченное изменение; сообщение описывает результат.
   Не коммитить чужие незавершённые изменения вместе со своими.
4. Не коммитить и не отправлять изменения напрямую в `main`. Включать работу только
   через PR из тематической ветки с целью, изменениями, проверкой и влиянием на
   экспериментальные выводы. Не сливать PR в `main`, если локальные или CI-тесты упали:
   сначала исправить ошибки и повторить проверки до успешного результата.
5. При наличии второго участника изменение проверяет хотя бы один другой человек.
   Пока участник один, допустима явная самопроверка с записью ограничений.
   Агент может помогать с review, но научные выводы и авторство подтверждают люди.
6. Не делать force-push в общую ветку. Конфликты в постановке, метриках и результатах
   обсуждать с авторами; не выбирать вариант только ради успешного слияния.

Remote: [GitHub](https://github.com/Nikita-812/diplom). Лицензия ещё не выбрана.
Для `main` на GitHub обязателен PR и успешный статус `checks` на актуальной ветке;
обход правила администратором запрещён. Одобрение второго участника пока не требуется.

## Личный вклад и публикации

В записи эксперимента или соответствующей работе указывать, кто выполнил:
постановку гипотезы, подготовку/разметку данных, реализацию метода,
проведение опытов, анализ и написание текста. Git-авторство само по себе
не доказывает научное авторство. Участие AI-инструментов отмечать в рабочих записях;
форму раскрытия в ВКР сверить с кафедрой.

Общие компоненты описывать и цитировать последовательно. Не выдавать результаты
соавтора за собственные, не представлять один и тот же эксперимент как три
независимых достижения. Состав авторов статьи определяется реальным вкладом
и согласуется участниками; намерение написать три статьи не задаёт авторство заранее.

Перед публикацией решить вопросы лицензий на код, веса и данные,
согласовать обнародование материалов с авторами и требованиями площадки.
Собственные ранее опубликованные результаты ссылать в ВКР; особенности проверки
заимствований изложены в [требованиях](vkr.md).

## Общее хранение

В Git хранятся документация, исходники, протоколы, небольшие разрешённые данные
и сводные результаты. Сырые корпуса, веса и объёмные выходы не коммитятся;
для них указываются доступное команде место хранения, источник/лицензия,
контрольная сумма и способ получения. Конкретное хранилище пока не выбрано.

Игнорируемые `.gitignore` каталоги не являются резервной копией.
Перед удалением рабочего каталога или переносом работы сохранить нужные артефакты.
