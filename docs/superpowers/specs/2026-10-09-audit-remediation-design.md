# Исправления по полному аудиту

## Цель и авторизация

Пользователь поручил выполнить план устранения находок полного аудита от 09.10.2026.
Baseline: родительский main b20c917fd800b16f757ae5af7a557f10bd71c535.
Изменения выполняются в отдельной ветке codex/full-audit-fixes, без переписывания истории.
Подготовка правок выполняется с участием AI-инструмента; научный review человеком остаётся отдельным этапом.

## Границы

Исправляем опубликованные материалы и импортированный agent-designer.
Исследовательский runtime и экспериментальные результаты этим изменением не создаются.
Темы, назначения авторов, домен, judge, численные допуски и бюджет не получают
статус утверждённого решения без пилота и согласования.
Новые правила интеграции и оценивания оформляются как проверяемый проект спецификации.

## Подсистемы и критерии готовности

1. Презентация: восстановленный v3 совпадает с проверенным оригиналом; новая v4 содержит
   16 слайдов, темы/вклад перед заключением, 18 минут для всей основной части из 14 слайдов.
   Заметки используют относительные источники; готовый Git blob проходит ZIP и SHA-256.
   Текущая версия собирается из единого JSON в документированной среде Artifact Tool 2.8.85.
   Исторические v1/v2 не переписываются; старые генераторы явно обозначены архивными.
2. Исследование: единый предлагаемый набор routing/context/adaptation; GraphRAG — расширение.
   Для каждой оси задан независимый изменяемый фактор и первичный контраст.
   Условный статус banking, разные приоритеты моделей по стендам и исключение Jev согласованы.
3. Контракты: различимые tool/respond/defer, формальные видимые tools, provenance RAG
   и отключённые hooks; протоколы меток D, selective scores, evaluator manifest,
   primary families и границы стоимости. Пилот-зависимые значения отмечены gate,
   а не заполняются вымышленными измерениями.
4. agent-designer: sample CLI работают; JSON Schema валидны по metaschema и сохраняют
   объявленные типы/items; planner поддерживает диапазон 1–20 и не выдаёт dangling IDs;
   enum сериализуются значениями, yaml создаёт файл; README inputs полноценны.
   Evaluator считает показатели tools по actions, результаты fixtures пересозданы из assets.
   Локальные изменения и исходная лицензия записаны в SOURCE/notice.
5. Wiki/CI: выбран tracked site, который пересобирается из текущих docs; CI проверяет
   содержательные страницы/навигацию/search/assets на соответствие новой сборке.
   Презентации проверяются ZIP/SHA-256, инструмент — регрессионными тестами.
   Сборка сайта и валидация не используют платных API или внешних моделей.
6. Review: независимая проверка всей ветки, исправление существенных замечаний,
   зелёные проверки и содержательные коммиты с Git-автором RealIlya.

## Проверяемые риски

Невалидные nested object schemas; массивы с identifier в описании; размеры team 1/2/10/20;
отсутствующие action telemetry; повреждённый PPTX, локальные notes paths и устаревшие site routes.
Ни один исправленный imported tool не выдаётся за экспериментальный harness.
