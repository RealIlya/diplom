# System One в языковых агентах

Исследовательский репозиторий для бакалаврских ВКР ФПМИ НГТУ:
**02.03.03 «Математическое обеспечение и администрирование информационных систем»**, кафедра ТПИ, защита в 2027 году.

Исследуем, при каких условиях модели типизированных вероятностных решений
(открытые кандидаты KEV и Laya) полезны внутри языкового агента и как их применение
влияет на итоговое качество, стоимость и задержку.

**Текущий этап:** подготовлены [контракт общей архитектуры](docs/gitmark/architecture.md)
и [подробный атлас адаптации System One на τ-knowledge](docs/gitmark/system-one-atlas.md)
с [интерактивными HTML-картами](site/research-atlas/index.html).
Текущая граница — отбор наблюдаемого KB-контекста; основной LLM ведёт диалог
и вызывает tools. Каноническая постановка и статус поддержки направления
руководителем — в [wiki](docs/gitmark/research.md).
Выполнен [технический offline CE-пилот](docs/gitmark/system-one-pilot.md): есть
[воспроизводимый стенд](experiments/system-one-pilot/README.md), raw результаты
BM25/frozen/CE и проверенные блокеры данных. Native агент и обобщение результата
на независимые банковские задачи пока не подтверждены.

## Результат проекта

Обязательный результат — формальная постановка задачи, воспроизводимый агент,
система измерения качества/стоимости/задержки и экспериментальное сравнение,
на основе которых готовятся самостоятельные ВКР. Отрицательный результат допустим.

Дообучение и изменение архитектуры выполняются под проверяемую гипотезу.
Три научные статьи и дальнейшее развитие исследования — перспективные цели,
а не обещанные результаты первой итерации.

## Работа с wiki в DSH

DSH — основной агент проекта. В чате можно сформулировать задачу обычным
сообщением или вызвать соответствующий навык в начале сообщения:

- `/kb-search выбор tools` — поиск по wiki ([kb-search](.agents/skills/kb-search/SKILL.md)).
- `/kb-doc уточни протокол оценки` — обновление документа ([kb-doc](.agents/skills/kb-doc/SKILL.md)).
- `/kb-build` — проверка wiki и индекса ([kb-build](.agents/skills/kb-build/SKILL.md)).
- `/kb-graph` — локальный граф связей ([kb-graph](.agents/skills/kb-graph/SKILL.md)).

Навыки DSH используют один и тот же GitMark CLI и канонические документы.
Если новый навык не появился в списке подсказок уже открытого чата, введите
`/kb-doc` или другое имя вручную: DSH загружает навыки проекта на следующем шаге.
Слеш-команды Claude Code из `.claude/commands/` остаются опциональными,
для работы в DSH открывать Claude Code не нужно.

## Локальная wiki

Сайт собирается из файлов `docs/`; исходный Markdown остаётся доступен напрямую.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-docs.txt
.venv/bin/mkdocs serve
```

Предпросмотр открывается по адресу <http://127.0.0.1:8000/>. Для проверки перед review:

```sh
.venv/bin/mkdocs build --strict
```

Поиск и проверки базы знаний (только стандартная библиотека Python):

```sh
python3 .claude/skills/kb-search/gitmark.py lint --strict
python3 .claude/skills/kb-search/gitmark.py index
python3 .claude/skills/kb-search/gitmark.py search 'τ-knowledge' -k 8
python3 .claude/skills/kb-search/gitmark.py stat
```

Индекс `.gitmark/` генерируется локально; сайт в `site/` хранится в Git.
Размещение сайта на хостинге отдельно не настроено. Инструменты dev-flow
и GitMark адаптированы из [very-ai-framework](https://github.com/redmadrobot-rnd/very-ai-framework/tree/4ebe7903d8725d45335ec7f726a06ad3f8d5bd53)
(коммит `4ebe790`, проверено 10.10.2026; лицензия скопированного кода —
[MIT](.claude/FRAMEWORK-LICENSE)). Серверный деплой и интеграции Codex/@claude
не настроены: в репозитории пока нет работающего приложения.

GitHub Actions проверяет Markdown, YAML, регрессионные тесты импортированного
инструмента, целостность презентаций, GitMark и соответствие хранящегося в Git сайта
строгой сборке wiki для каждого pull request и после изменений в `main`.
CI не запускает научные эксперименты и не использует платные API.
