# Протокол API-пилота v1 — 25.10.2026

Поручение инициатора: полный путь native banking/BM25 → карточки → две LLM →
локальная проверка. Автор инженерной реализации и конкретизации: агент Codex.
Это технический пилот, без обучения и без человеческих меток от агента.
Канонические ограничения: [профили](../../docs/gitmark/system-one-pilot.md#api-pilot-profile),
[контекст](../../docs/gitmark/architecture.md#context-contract-v0),
[журнал](../../docs/gitmark/research.md#запись-эксперимента).

## План и решения агента до прогнозов

1. Проверить hashes pinned исходников и действующего manifests-v3. Выбрать
   первые 5 train-задач разных семейств по SHA256(seed=25, family, task ID).
   Порядок не зависит от результатов. Один эпизод на задачу, 80 шагов,
   5 ошибок tools, timeout 900 секунд; без автоматических повторов.
2. Штатные LLMAgent, UserSimulator, Orchestrator и BM25 остаются исходными.
   Меняется только HTTP transport для постоянного учёта и ограничения оплаты.
   Агент DeepSeek low, simulator reasoning disabled, max_tokens=2048 в обеих
   ролях. Native evaluator ENV отдельно; NL judge не запускается и итоговый
   полный reward не заявляется. При ошибке сохраняется частичная траектория.
   Обновление исполнения: официальный DeepSeek endpoint дал HTTP404 из-за
   account training policy. После отдельного прямого разрешения инициатора
   закреплён **тот же snapshot у `deepinfra/fp8`**, без fallback и изменения
   privacy settings; DeepSeek-разметчик использует этот же endpoint. Qwen
   остаётся `deepinfra/bf16`. Смена provider/quantization явно входит в manifests.
3. Общая SQLite `artifacts/system-one-pilot/authorized-series-20261025.sqlite3`
   хранит отдельные лимиты collection=$1, annotation=$0.50 независимо от `--root`.
   Перед HTTP — транзакционная резервация по верхним тарифам endpoint,
   без кеша/скидок: не меньше $0.30/$1.20 и $0.20/$2.50 за миллион input/output.
   Input upper bound: UTF-8 bytes JSON + 4096 + 256 на сообщение/tool,
   включая сериализованные схемы tools. Output включает reasoning.
   provider max_price ограничивает тариф; неизвестный исход удерживает резерв
   и останавливает серию. Сохранённый ответ повторно не оплачивается.
   После расследования определённый HTTP4xx-отказ может быть закрыт отдельной
   append-only квитанцией **с сохранением всего резерва как расходованного
   лимита**, без заявления нулевой фактической стоимости. Исходная запись не
   меняется и тот же call ID не повторяется. Это позволяет новый целевой
   диагностический вызов после установления причины, а не слепой retry.
4. Взять до 3 различных retrieval-состояний на эпизод, равномерно по порядку
   KB-событий после завершения tool batch. Состояние по контракту v0: все user
   реплики и ближайшая предыдущая речевая assistant, последний поиск, все
   non-KB tool outcomes. Только allowlist наблюдений, без raw_data, gold,
   reward, simulator instructions и будущих сообщений.
   До новых прогнозов представление уточнено до `context-v0-structural-v2`:
   сохранён native error flag; failed KB search остаётся наблюдаемой ошибкой,
   не документом и не причиной исчезновения ранее полученного пула.
5. Сначала целый документ, затем структурное разбиение при overflow 4096.
   Консервативно: сохранять преамбулу, заголовки и все абзацы с условиями/
   исключениями в каждой части; неделимый блок отклонять. Никакого word chunking.
   Guard cues включают assume/subject/provided/depend/before/after/when/where;
   это проверяемое структурное приближение, не доказательство семантической
   полноты. Человек отдельно отмечает потерянные условия как дефект данных.
   Отдельные STATE_OVERFLOW/CANDIDATE_OVERFLOW; отчёт по всему пулу 1024/4096/8192.
   Один профиль 4096 для frozen/adapted; runtime train-only, без обучения.
6. До 30 admitted карточек: round-robin по эпизодам и снимкам после сортировки
   stable hash(seed=25,row ID), не более 10 на эпизод. Минимум 20 — цель,
   при нехватке пригодных наблюдений сообщить фактический размер.
7. Одинаковый input и rubric-v1 каждой LLM независимо; output 2048, reasoning low.
   Исходные ответы неизменны. Ошибка JSON/цитаты/finish_reason — technical_error;
   автоматического исправляющего повтора нет (можно расследовать с новым run ID).
8. Все спорные, uncertain и technical_error — человеку; дополнительно 7 случайных
   совпадений с seed=25 вслепую. Это проверка процесса без статистической гарантии.
   Если человек находит общую ошибку моделей, помечает дефект/причину; очередь
   приостанавливается для пересмотра рубрики и новой версии затронутых меток.

## Рубрика v1

Английский точный текст и JSON schema: `scripts/system_one_pilot/rubric-v1.txt`.
Полезность относится к текущей потребности, выраженной в наблюдаемом диалоге,
а не автоматически к последней query. Частичное применимое правило/исключение
полезно без требования полного решения задачи. Явно несовместимый продукт/
условие — irrelevant; неизвестная применимость и противоречащие сведения —
uncertain. Дефект представления отдельно от семантической неопределённости.
Цитата должна буквально существовать в state или candidate.

## Зафиксированное изменение формата после первой серии

Rubric-v1 не менялась. Первая json_object серия дала 18 technical_error/60:
схема/цитаты/length. До нового вызова сохранён `annotation-plan-v2.json` с хешем
прежней очереди и strict JSON schema. Агент решил повторить **все** те же 30
входов независимо обоими разметчиками, без передачи прежних ответов; новая
версия сохраняется отдельно в `annotations-v2`, call ID содержит `schema-v2`.
Это повтор в прежнем отдельном лимите $0.50, не выбор примеров по удачному ответу.
Получено 59 valid и 1 technical quote error; v1 не исправлялась и не удалялась.
Рабочая review DB импортирует v2 с проверкой ledger/model/call/input/rubric/schema.
